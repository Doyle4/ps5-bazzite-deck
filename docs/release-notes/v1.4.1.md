**Pre-release.** v1.4.0 broke Wi-Fi on consoles with the IW620 chip (most original PS5s): networks are seen but won't connect, and the first start gets stuck on the Steam login. This build is for the people affected, to confirm the fix; it goes stable once it does.

## What's changed since v1.4.0
- **IW620 consoles: the Linux-only Bluetooth address is off by default.** It's the suspect for the Wi-Fi problem: a vendor command to the Wi-Fi/Bluetooth combo chip at every boot. `ps5-bt-address on` switches it back on if you want one DualSense for PS5 and Linux and your Wi-Fi is fine without it. MediaTek consoles are unaffected (the kernel sets their address itself).
- **USB never sleeps by default** (`usbcore.autosuspend=-1`, added to `cmdline.txt` by the image and the updater): fewer disconnects and freezes with USB drives and dongles.
- **Wi-Fi power saving off** whenever Wi-Fi comes up: with it on, the IW620 throttles to ~100 Mbit/s instead of ~700 (thanks to thelonlybud for the tip).
- **Warm reboot** (still optional, `ps5-warm-reboot on`): systemd now does the kexec itself (no more "Transport endpoint is not connected"), and on IW620 consoles Wi-Fi is repaired automatically after a warm reboot. Bluetooth on those consoles still needs a cold start afterwards; the command says so.

## Known issues
- IW620 consoles: if Wi-Fi still won't connect on this build, send `journalctl -b --no-pager | grep -i -e wlan -e NetworkManager | grep -i -e fail -e error -e timeout | head -20` in Discord; then the suspect was wrong and the search continues.
- VRR isn't in a release yet; it continues in the vrr-test builds.
