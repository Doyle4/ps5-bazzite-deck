v1.4.0 broke Wi-Fi on consoles with the IW620 chip (most original PS5s): networks were seen but wouldn't connect, and the first start got stuck on the Steam login. **v1.4.1 fixes that (confirmed by testers) and replaces v1.4.0.**

## What's changed since v1.4.0
- **IW620 consoles: the Linux-only Bluetooth address is off by default.** It caused the Wi-Fi problem: a vendor command to the Wi-Fi/Bluetooth combo chip at every boot. `ps5-bt-address on` switches it back on if you want one DualSense for PS5 and Linux and your Wi-Fi is fine without it. MediaTek consoles are unaffected (the kernel sets their address itself).
- **USB never sleeps by default** (`usbcore.autosuspend=-1`, added to `cmdline.txt` by the image and the updater): fewer disconnects and freezes with USB drives and dongles.
- **Wi-Fi power saving off** whenever Wi-Fi comes up: with it on, the IW620 throttles to ~100 Mbit/s instead of ~700 (thanks to thelonlybud for the tip).
- **Warm reboot** (still optional, `ps5-warm-reboot on`): systemd now does the kexec itself (no more "Transport endpoint is not connected"), and on IW620 consoles Wi-Fi is repaired automatically after a warm reboot. Bluetooth came back after warm reboots in testing too; if it's ever missing, power off and run the loader.

## Known issues
- One report of no Wi-Fi on a PS5 Slim (12.20) is still open. If Wi-Fi won't connect on your console, send `journalctl -b --no-pager | grep -i -e wlan -e NetworkManager | grep -i -e fail -e error -e timeout | head -20` in Discord.
- **First start:** after joining Wi-Fi, Steam updates itself behind a blank screen for several minutes. Don't power off there.
- VRR isn't in a release yet; it continues in the vrr-test builds.
