## What's new
- **VRR test 21:** a measurement of what the GPU really sends while VRR is on, to find out whether the missing piece is the GPU or the HDMI chip. Only active with ` hdmi.vrr_test=1`; without it nothing changes.

## VRR test
For testers with an original PS5 or Slim with the **FLAVA3** HDMI chip (`ps5-report` shows it) and a TV with VRR. VRR doesn't work yet; this test answers one question: **does the GPU actually vary the frame length?** Every 2 seconds the kernel logs the measured frame intervals, `frame length VARIES` or `FIXED`. With a game at 60 fps on a 120 Hz mode, VARIES with about 16.7 ms means the GPU does its part and the problem is the HDMI chip; FIXED at 8.3 ms means the GPU never sends variable timing.

**Switch on:** add ` hdmi.vrr_test=1` to the end of `cmdline.txt` (one line), power off and start with the loader. For this test, **leave the 40-CU unlock off** (`amdgpu.ps5_cu_unlock`): it can cause flicker on its own.

**Test:**
1. **TV:** VRR on for that HDMI input (LG: "VRR & G-Sync" and "AMD FreeSync Premium"; Samsung: Game Mode + FreeSync; Sony: VRR in the input settings).
2. **Game Mode:** HDR off, a 120 Hz mode (1080p120 or 1440p120), and note which.
3. Start a fullscreen game, limit it to **60 fps** (quick access menu → Performance), switch **VRR on**, play for a minute. Then run `vrr-report`.
4. **The chip's own VRR mode:** `echo 1 | sudo tee /sys/module/hdmi/parameters/vrr_chip`, VRR off and on again in the game, a minute, `vrr-report` again.

**Report:** post both `vrr-report` files in #bazzite-prereleases-experimental, saying which step each is. The lines that matter are `PS5 VRR DRR:`.

**Switch off:** remove ` hdmi.vrr_test=1` from `cmdline.txt` and start cold.

## Known issues
- **Colours too dark, shadows crushed, on TVs whose RGB range / black level is on "Auto"** (most current TVs): the PS5 told the TV "limited range" by mistake. Fixed in v1.5.3. Until then, set the TV's black level / RGB range for that input to **High / Full**, or add ` hdmi.rgb_range=0` to `cmdline.txt` (remove it again after updating to v1.5.3).
- **GPU page faults when Game Mode starts** (coming from the desktop): Game Mode's X window thread (`gamescope-xwm`) triggers them, the graphics queue times out and is reset, and the screen can freeze for a while. Being investigated.
- **Garbled picture in Game Mode on some older LG TVs with "HDMI Ultra Deep Colour" on** (the desktop is fine): switching Deep Colour off fixes it for now.
- **Steam downloads can get slower after switching to the desktop and back**, while Wi-Fi itself stays at full speed. A cold start brings the speed back.
