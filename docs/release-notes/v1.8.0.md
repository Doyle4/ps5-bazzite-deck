## What's new
- **ALLM:** on consoles with the FLAVA3 HDMI chip, the TV switches to its game mode by itself, if it supports ALLM. It's the same HDMI signal the PS5 system sends. ` hdmi.allm=0` in `cmdline.txt` switches it off.
- **PS5 Pro (needs testers):** GPU support (64 compute units, GPU clock and temperature) from upstream's work by Borchev, and the Pro's own GPU firmware: the loader dumps it to the boot partition, and the first boot adds it to the initrd; start Linux with the loader once more to use it. Wi-Fi (MediaTek MT7925) and the internal Bluetooth (QuartConz's driver work) are in too, all untested on our build so far: keep Ethernet and a wired controller at hand for the first start. Nothing changes on other consoles.
- **`ps5-bt-address`** (IW620 consoles) warns about the cold-boot reconnect problem, and `ps5-bt-address status` shows the controller's current address.

## Testing
- **ALLM:** with a TV that supports it, the TV's game mode should switch on by itself when Linux starts and after a resolution change. VRR and 4K120 should work as before. Report your TV model either way.
- **PS5 Pro:** Wi-Fi in the network settings, a DualSense pairing over Bluetooth (PS + Create). After the first boot, `journalctl -u ps5-stage-viola-fw` should say the firmware was added; after starting with the loader again, `sudo dmesg | grep -i -e viola -e 64cu`. Post `ps5-report` in #bazzite-problems.

## Known issues
- **PS5 Pro:** first build, untested on a Pro; tell us what works and what doesn't.
- **VRR, 4K120 and ALLM on consoles with the VERDE HDMI chip** aren't supported yet, so they aren't offered there.
- **GPU page faults when Game Mode starts** (coming from the desktop): the screen can freeze for a while. Being investigated.
- **Sleep uses a lot of power** (the GPU stays on). For longer breaks, power off.
