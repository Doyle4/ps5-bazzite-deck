## VRR test
For **FLAVA3** consoles with ` hdmi.vrr_test=1` in `cmdline.txt` and a TV with VRR. Test 24 matched every visible message of Sony's VRR switch except the **pre-block**, whose constants (`0x7061`, `0x7215`, `0x6207`, `0x621b`, `0x7070`) came from a 4K capture. This build can send any pre-block 1:1 instead of ours, set at runtime (`P=/sys/module/hdmi/parameters`), then **VRR off and on again in the game**.

**Before each step:** a fullscreen game limited to **60 fps**, HDR off, `echo 1 | sudo tee $P/vrr_chip`. Note your mode (the pre-block depends on it).

1. **Stock's pre-block for your mode** (from hsgodd's stock capture, hex, the whole message or just its body): `echo <hex> | sudo tee $P/vrr_prep_raw`, VRR off/on, wait a minute. Picture? TV says VRR?
2. **Bisecting:** start from our own pre-block and change one constant at a time. Ours at 1440p120, as a starting point (body only): `012d0002020903010170010303022002060270615a000270700000037077907193017215010162078001621b20`
3. **Back to ours:** `echo | sudo tee $P/vrr_prep_raw` (empty).

**Report:** `vrr-report` after each step; the line `VRR prep RAW (… status 00 …)` confirms the chip took it. With ` hdmi.icc_trace=1` during the switch, the whole sequence can be lined up against the stock capture.

**No picture after VRR goes on?** Switch VRR off over SSH (it comes back within about a minute): `ssh -t ps5@<PS5 IP> 'export XDG_RUNTIME_DIR=/run/user/$(id -u) GAMESCOPE_WAYLAND_DISPLAY=gamescope-0; gamescopectl adaptive_sync 0'` (`adaptive_sync 1` switches it on again).

**Switch off:** remove ` hdmi.vrr_test=1` from `cmdline.txt` and start cold.

## Known issues
- **GPU page faults when Game Mode starts** (coming from the desktop): Game Mode's X window thread (`gamescope-xwm`) triggers them, the graphics queue times out and is reset, and the screen can freeze for a while. Being investigated.
- **Garbled picture in Game Mode on some older LG TVs with "HDMI Ultra Deep Colour" on** (the desktop is fine): switching Deep Colour off fixes it for now.
- **Steam downloads can get slower after switching to the desktop and back**, while Wi-Fi itself stays at full speed. A cold start brings the speed back.
