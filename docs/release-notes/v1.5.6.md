## What's new
- **VRR tests 25b and 26:** stock's VRR arming sequence plus our own pre-block, and a way to send any message to the HDMI chip's controller at runtime, to find how Sony triggers that sequence. Only active with ` hdmi.vrr_test=1`; nothing changes otherwise.

## VRR test
For **FLAVA3** consoles with ` hdmi.vrr_test=1` in `cmdline.txt` and a TV with VRR. Test 25 showed the HDMI chip's controller (the EMC) accepts Sony's VRR arming sequence (id `0x30`) but never runs it: stored sequences only run when a trigger is bound to them, and our trigger table has no `0x30`. Test 26 registers the sequence and binds it to the known trigger bits, all at runtime (`P=/sys/module/hdmi/parameters`, everything as root).

**Before the steps:** Game Mode with VRR **off** (Settings → Display), a fullscreen game limited to **60 fps**, HDR off. Then switch VRR on and off over SSH so you keep a picture to come back to:
`ssh -t ps5@<PS5 IP> 'export XDG_RUNTIME_DIR=/run/user/$(id -u) GAMESCOPE_WAYLAND_DISPLAY=gamescope-0; gamescopectl adaptive_sync 1'` (and `adaptive_sync 0` to switch it off; the picture comes back within about a minute).

1. **Register sequence 0x30 now** (outside a mode set, as stock does at init): `echo 421000000300860181001a140075000104711001306d0b00020802010170110703080301007011ff020c0202017204e00170110f03080301007011ff02110203017204e002723100000172276102090301017226808002090301017228303002090301017225c0c002090301017226607002080201017204c10308030100720441 | sudo tee $P/icc_send`
2. **Bind it to all seven trigger bits** (keeps our existing bindings): `echo 00400001043c020e317ab808327ab005337aa005347ae101357ae201367ae001377c0005307ab808307ab005307aa005307ae101307ae201307ae001307c0005 | sudo tee $P/icc_send`
3. `echo 1 | sudo tee $P/vrr_chip`, switch VRR on over SSH, wait a minute. Picture? TV says VRR?
4. **If yes, narrow it down:** restore the table (below), register again, bind one trigger at a time:
   - trigger `0x7ab8/08`: `0028000104240208317ab808327ab005337aa005347ae101357ae201367ae001377c0005307ab808`
   - trigger `0x7ab0/05`: `0028000104240208317ab808327ab005337aa005347ae101357ae201367ae001377c0005307ab005`
   - trigger `0x7aa0/05`: `0028000104240208317ab808327ab005337aa005347ae101357ae201367ae001377c0005307aa005`
   - trigger `0x7ae1/01`: `0028000104240208317ab808327ab005337aa005347ae101357ae201367ae001377c0005307ae101`
   - trigger `0x7ae2/01`: `0028000104240208317ab808327ab005337aa005347ae101357ae201367ae001377c0005307ae201`
   - trigger `0x7ae0/01`: `0028000104240208317ab808327ab005337aa005347ae101357ae201367ae001377c0005307ae001`
   - trigger `0x7c00/05`: `0028000104240208317ab808327ab005337aa005347ae101357ae201367ae001377c0005307c0005`
5. **25b instead:** `echo 421000000300860181001a140075000104711001306d0b00020802010170110703080301007011ff020c0202017204e00170110f03080301007011ff02110203017204e002723100000172276102090301017226808002090301017228303002090301017225c0c002090301017226607002080201017204c10308030100720441 | sudo tee $P/vrr_prep_raw; echo 1 | sudo tee $P/vrr_prep_keep`, then VRR on: stock's sequence *and* our pre-block at the mode set.

**Restore our trigger table:** `echo 0024000104200207317ab808327ab005337aa005347ae101357ae201367ae001377c0005 | sudo tee $P/icc_send`. A cold start restores everything anyway.

**Watch for side effects:** with the shotgun binding, sequence `0x30` may also run on other events (plugging, the TV waking up). If anything behaves oddly, restore the table or start cold.

**Report:** the log lines `ICC send (… ret 0 …)` confirm each message; then `vrr-report` after step 3, posted in #bazzite-prereleases-experimental with the step number.

**Switch off:** remove ` hdmi.vrr_test=1` from `cmdline.txt` and start cold.

## Known issues
- **GPU page faults when Game Mode starts** (coming from the desktop): Game Mode's X window thread (`gamescope-xwm`) triggers them, the graphics queue times out and is reset, and the screen can freeze for a while. Being investigated.
- **Garbled picture in Game Mode on some older LG TVs with "HDMI Ultra Deep Colour" on** (the desktop is fine): switching Deep Colour off fixes it for now.
- **Steam downloads can get slower after switching to the desktop and back**, while Wi-Fi itself stays at full speed. A cold start brings the speed back.
